# "○○가 본 너": 연인이 플레이어를 판단하는 기능

- **상태:** 1단계 구현 (판단 카드 + 맞아/좀 달라)
- **작성일:** 2026-11-21
- **관련:** [relationship-engine](https://github.com/happy7yong/relationship-engine) (B)의 Belief, `server/belief.ts`, `src/BeliefCard.tsx`

## 1. 의도

relationship-engine(B)이 결국 하고 싶은 것은 **NPC가 함께 겪은 일로 플레이어를 자기 방식으로 이해하는 것**이다. B에서는 이것을 Belief(가설)라고 부른다.

> Belief: 경험을 근거로 NPC가 형성한 사용자에 대한 해석. 틀릴 수 있으며 반례와 정정으로 수정된다.

B는 지금 Phase 0이고 Belief는 v0.2 예정이다. 이 게임은 다섯 마디짜리 아주 작은 판이지만, 대화가 끝난 뒤 연인이 "내가 본 너는 이런 사람 같아"라고 말하게 하면 **Belief를 실제 사람 100명에게 먼저 시험**해 볼 수 있다.

게임으로서의 의도도 있다.

- 결과가 "54% 움직였다"라는 숫자에서 **"나를 이렇게 봤구나"**로 바뀐다. 처음 기획한 "말의 무게"가 직접 와닿는다. 내가 고른 말들이 모여 상대가 나를 이렇게 판단했다는 것이니까.
- "다르게 말하면 나를 다르게 볼까?"라는 재도전 이유가 생긴다.

테스트에서 나온 피드백: **NPC의 판단에 타당한 근거가 없어서 아쉬웠다.** 그래서 1단계의 핵심은 근거다.

## 2. 원칙 (B에서 가져온 것)

| 원칙 | B의 근거 | 이 기능에서 |
| --- | --- | --- |
| 판단에는 근거가 있다 | 판단의 근거를 기록한다 (README 설계 원칙) | 판단마다 근거 마디 번호와 그 마디에서 플레이어가 **실제로 한 말을 그대로** 붙인다. 원문에 없는 인용은 코드가 거부한다 |
| LLM은 제안, 엔진이 검증 | D-011 | 인용 검사, 진단 라벨 검사는 코드가 한다 |
| 정보 경계 | 엔진 규칙 | 이 대화에 없던 과거·습관·성격을 지어내지 않는다 ("원래 ~잖아" 금지) |
| NPC 자신의 관점 | 공통 원칙 "같은 사건에도 NPC마다 다른 의미", "잘못된 추측과 오해도 가능" | 연인의 Core(가치관·말투)로 본 해석이다. 화면에 "○○의 관점이라 틀릴 수 있어요"를 먼저 밝힌다 |
| 한 번에 완전히 이해하지 않는다 | 공통 원칙 5 | 판단은 2~3개, 다섯 마디에서 실제로 보인 것만 |
| 성격 유형으로 연기하지 않는다 | 사와무라 Core "ENFP를 연기하게 만들지 않는다" | MBTI, 애착 유형, 불안형·회피형, 자존감, 트라우마 같은 라벨은 코드가 거부한다 |

## 3. 구현

### 3.1 마디마다 쌓는 관찰 (B의 Episode 역할)

마디마다 연인의 응답에 `noticed`(이번 말에서 플레이어에 대해 알게 된 것, 30자 이내)를 함께 받는다. 예: "서운한 건 돌려 말하지 않음", "방법부터 꺼냄". `turns.noticed`에 저장된다.

마지막에 한 번에 판단하지 않고 대화 중에 관찰을 쌓아 두는 이유: 근거가 그 순간의 반응에서 나오므로 엉뚱한 판단이 줄고, 나중에 어떤 마디에서 무엇을 알게 됐는지 추적할 수 있다.

### 3.2 판단 생성 (`server/belief.ts`)

판이 끝나면 리포트를 먼저 보여 주고, 리포트 아래 카드에서 `/api/belief`를 부른다.

- **입력:** 연인의 Core, 최종 결과(움직인 %), 마디별 플레이어 말 · 연인 대답 · 알게 된 것 · 속마음
- **출력:**
  - `summary`: "내가 본 너는 ~" 1~2문장
  - `points` 2~3개: `claim`(관찰), `turn`(근거 마디), `quote`(그 마디에서 한 말 그대로), `why`(왜 그렇게 봤는지, 연인 말투)
  - `expectation`: "다음에 내가 또 연락 못 하면, 너는 아마 ~" (B의 Expectation, v0.3 개념)
- **검사:**
  - `quote`가 그 마디 플레이어 말에 실제로 있는지 (공백·문장부호 차이는 무시)
  - 진단 라벨이 없는지
  - 첫 시도는 모든 판단이 진짜 근거를 가져야 통과. 마지막 시도는 근거가 맞는 판단만 남기고, 하나라도 있으면 통과. 하나도 없으면 실패("다시 불러오기")
- **저장:** 한 번 만든 판단은 `plays.belief`에 저장하고 다시 돌려준다. 같은 판에서 판단이 바뀌지 않고 비용도 한 번만 든다. 시도별 원문은 `llm_calls`(call_type `belief`)에 남는다.

### 3.3 화면 (`src/BeliefCard.tsx`)

리포트 맨 아래 어두운 카드.

1. 제목 "○○가 본 너", 안내 "다섯 마디 동안 ○○가 느낀 대로예요. ○○의 관점이라 틀릴 수 있어요."
2. summary
3. 판단마다: 관찰 → **근거 · n번째 말 "인용"** (누르면 그 마디 카드로 이동해 강조) → 왜 그렇게 봤는지
4. 예상 한 줄
5. "○○가 본 너, 맞는 것 같아요?" **[맞아] [좀 달라]** → `plays.belief_feedback`

## 4. 이걸로 알 수 있는 것

- **판단이 맞게 느껴지는가:** `belief_feedback`의 agree 비율. NPC의 해석이 실제 사람에게 와닿는지에 대한 첫 데이터다.
- **어떤 근거가 납득되는가:** agree/disagree별로 근거 마디의 전략 라벨, 움직인 %를 비교한다.
- **연인의 성별에 따라 다른가:** `partner`별 agree 비율.
- **근거 품질:** `llm_calls`에서 첫 시도가 근거 검사로 거부된 비율 = 모델이 근거를 지어내는 빈도.

## 5. 다음 단계

- **2단계 (B v0.2의 "반례로 고친다"):** "좀 달라"를 누르면 플레이어가 한 줄로 정정하고, 연인이 "아 그래? 그럼…" 하고 판단 하나를 고쳐 말한다. 정정 전후를 저장해 Belief 수정이 납득되는지 본다.
- **판단 품질 평가:** 자동 검사는 근거 실존과 금지 라벨만 본다. 자연스러움·납득도는 사람이 본다 (B의 D-068과 같은 역할 분담).
- **B로 가져가기:** 근거 검사(인용 실존), 진단 라벨 거부, "관점이라 틀릴 수 있음"의 표시 방식을 B의 Belief 계약 초안에 반영한다.
