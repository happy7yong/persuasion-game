# 윤재·서아 캐릭터 설계 의도와 현재 구현 점검

- **작성일:** 2026-11-22
- **상태:** 의도 확정, 현재 구현 분석 완료. 변경은 아직 하지 않음 (§4의 후보만)
- **관련:** [dialogue-architecture.md](dialogue-architecture.md) (대화 엔진 구조), `server/content.ts` (Core · 원칙 · 끝맺음 지침), `server/npc.ts` (프롬프트 조립 · 검증), `server/ledger.ts` (장부 · 마음 규칙), `server/rules.ts` (끝맺음 선택 · 점수)

## 1. 의도

> 윤재와 서아가 상황별 정답을 조합하는 캐릭터가 아니라, **자신만의 가치관과 감정, 욕구를 가진 일관된 인물과 대화하고 있다는 경험**을 주고 싶다.
> 캐릭터가 어떤 말을 해야 하는지 알려 주기보다, **어떤 사람이고 지금 무엇을 느끼며 어떤 상황에 있는지**를 충분히 주고 그 결과로 나오는 반응을 보고 싶다.

| # | 원칙 | 뜻 |
| --- | --- | --- |
| I1 | 상태에 **맞는** 대사가 아니라 상태에서 **비롯된** 대사 | 정해진 반응을 고르는 것이 아니라, 내면에서 반응을 만든다 |
| I2 | Core는 규칙집이 아니라 판단 기준 | 무엇을 중요하게 여기고 원하고 두려워하는지. 상황을 해석하는 방식에 영향을 주되 행동을 강제하지 않는다. 소중히 여기면서도 투덜거릴 수 있다 |
| I3 | 감정 수치는 조건문이 아니다 | 피곤 3이 곧 짧은 대답은 아니다. 여러 감정·Core·욕구·맥락이 함께 하나의 반응을 만든다. 같은 수치라도 직전에 들은 말과 남은 문제에 따라 다르게 반응한다 |
| I4 | 해석과 욕구가 중심 | **Core + 현재 상태 + 맥락 → 상황 해석과 욕구의 형성·충돌 → 반응.** 같은 말을 윤재와 서아가 다르게 받아들인다. 이해받고 싶으면서 더 설명하기는 싫은 것처럼 욕구가 부딪칠 수 있다 |
| I5 | 생성 프롬프트에는 예시 대사를 두지 않는다 | 상황별 모범 대사·감정별 표현 예시·수치별 반응 공식을 빼고, 인물의 성격·상태·판단 원칙을 준다. **테스트의 예시 대화는 별개다** |
| I6 | 검증기는 판단을 대신하지 않는다 | 확정된 사실과 대화 상태에 **명백히 모순되는** 출력만 막는다. 정리된 주장은 반복하지 않아도 서운함은 남을 수 있고, 그 선택은 생성 모델이 한다 |
| I7 | 자유는 무작위가 아니다 | 반응이 달라도 "그 캐릭터라서 그렇다"고 납득돼야 한다. 반드시 화해로 가지 않는다. 관계는 나아질 수도, 그대로일 수도, 나빠질 수도 있다 |

**구조를 바꾸는 기준:** 새로운 계층·수치·검증기를 더하는 것 자체가 목표가 아니다. 지금 있는 Core · State · 장부 · 대화 이력으로 충분한지 먼저 확인하고, 부족하다는 근거가 있을 때만 넓힌다. **가장 적은 구조 변경으로 가장 큰 효과.**

## 2. 현재 구현 점검 (2026-11-22, 프롬프트 `ledger@1`)

근거는 코드·프롬프트 원문과, 최근 이틀 DB에 저장된 실제 NPC 대사 110마디다.

### Q1. Core는 판단 기준인가, 규칙집인가 → **반반. 가치·욕구는 판단 기준인데, 행동 순서와 결말 시점을 정한 규칙이 섞여 있다**

판단 기준으로 잘 쓰인 부분 (유지):
- "중요하게 생각하는 것", "원하는 것과 화가 나는 조건", "미안함과 억울함은 동시에 있을 수 있다" — 가치·욕구·두려움이고 행동을 정하지 않는다.
- 공통 원칙 "독립적 판단과 행동" — 결과를 미리 정하지 말고 감정이 무엇을 말할지에 영향을 준다. I1·I7과 같다.

규칙집에 가까운 부분:
- **"행동의 기본 순서"** (두 Core 모두): "상대 말을 들음 → 먼저 미안함·억울함·피곤함 중 하나가 튀어나옴 → 짧게 반응함 → 상대가 말한 이유를 들음 → 그제야 자기 몫을 구분해 인정". 반응의 진행 순서를 정해 둔 것이다.
- **결말 시점 고정**: "자신이 일부러 피한 것은 아니라는 입장과 … 마지막 대화 전까지 유지한다" (두 Core 모두). 플레이어가 무슨 말을 해도 4마디까지 이 입장은 못 바꾼다.
- "해결책은 먼저 제안하지 않는다", "사과할 때는 무엇을 사과하는지 명사를 분명히 말하고" — 판단이 아니라 행동 지정.

### Q2. 감정 수치는 서로 섞여 반응을 만드는가 → **대사 프롬프트에서는 수치→행동 직결이 없다. 대신 점수 구간→행동 직결과, 캐릭터와 상관없는 수치 갱신이 있다**

- 대사 프롬프트의 "지금 마음"은 수치만 주고 "Core의 성향대로 이 마음이 방금 말을 어떻게 듣게 하는지는 네가 판단한다"고 맡긴다. 예전의 "방어심 3이고 미안함 1 이하면 이렇게 말해라" 분기는 장부 구조로 바꾸며 지웠다. **I3을 지킨다.**
- 그러나 **`BAND_GUIDE`는 점수 구간을 행동으로 직결한다**: "흔들리고 있다. 말끝이 흐려지고, 상대 말이 맞을 수도 있다는 기색이 보인다" 등. 이 구간은 마음 수치가 아니라 플레이어가 쌓은 설득 점수에서 나온다. 매 마디 대사 프롬프트에 들어간다.
- **수치를 바꾸는 규칙이 윤재와 서아에게 같다** (`ledger.ts` `nextMind`): "질문 → 방어심 −1", "비난 → 방어심 +1"이 누구에게나 똑같이 적용된다. 같은 말을 둘이 다르게 받아들인다(I4)는 것이 수치에는 반영되지 않는다. 시작 수치도 둘이 같다(피곤 3 · 미안함 1 · 방어심 3 · 챙김 2 · 열림 1). 서아 Core에는 "답장을 미룬 것은 미안하다"고 쓰여 있는데도.
- 수치는 대상이 없는 전체 값이다. "누구에게 어떤 감정"(I3)은 장부의 "누가 무엇을" 쪽이 일부 대신한다.
- Core의 "피곤하면 설명이 짧아지고"(윤재 말투), "피곤하면 말이 더 짧아지고"(서아 상태)는 성향 서술이지만, 피곤은 한 판 내내 3으로 고정돼 사실상 "늘 짧게"가 된다.

### Q3. 해석하고 욕구를 부딪치는 과정이 있는가 → **거의 없다. 속마음을 대사 "뒤에" 쓴다**

- 대사 출력 형식(`OUTPUT_FORMAT`, `NPC_JSON_SCHEMA`)은 `beats`(대사) → `thought`(속마음) 순서다. 구조화 출력은 이 순서대로 생성되므로 **말을 먼저 하고 속마음은 나중에 붙인다.** 해석이 반응을 만드는 게 아니라 반응을 사후에 설명한다. I4의 순서와 반대다.
- 1차 발화 분석은 Core 없이 중립적으로 "무슨 말이었나"만 기록한다(설계 의도대로). 그래서 "윤재에게 어떻게 들렸나"를 만드는 단계는 2차밖에 없는데, 그 2차가 해석을 나중에 쓴다.
- 욕구는 Core에 고정된 목록으로만 있다. 지금 이 말을 듣고 무엇을 원하게 됐는지, 그게 다른 바람과 부딪치는지를 쓰는 자리가 없다.

### Q4. 예시 대사·정해진 화해 흐름이 얼마나 있는가 → **생성 프롬프트에 대사 예시 6곳, 그리고 결말을 고정하는 장치 5곳. 실제 대사가 예시를 따라간다는 근거가 있다**

생성 모델이 보는 예시 대사·행동:

| 위치 | 예시 |
| --- | --- |
| `ENGINE_RULES` 발화 속 역할 확인 | "내가 X해달라는 거지", "그 정도는 내가 해볼 수 있어" |
| `COMMON_PRINCIPLES` 설득될 수 있음 6 | "내가 일부러 너를 무시한 것처럼 말한 건 받아들이기 어렵다" |
| 윤재 Core 갈등과 잘못을 인정하는 방식 | "일부러 그런 건 아니잖아", "그렇게 느꼈구나" |
| 서아 Core 사람을 대하는 방식 | "라떼를 시켜 두거나, 빨대를 꽂아 두거나, 잔을 슬쩍 밀어 주는 식" |
| `MOVE_GUIDE.ask` | "무엇이 제일 서운했는지처럼" |
| `MOVE_GUIDE.concede` | "…그건 그렇네", "알았어 알았어" |

실제 대사에 나온 횟수 (최근 이틀 110마디):
- 행동 묘사가 있는 95마디 중 **88마디(93%)에 라떼·빨대·잔·컵.** 서아 Core의 예시 행동이 윤재까지 포함해 거의 모든 행동 묘사가 됐다. 장면에 라떼가 있는 건 사실이지만, 다른 몸짓이 거의 나오지 않는다.
- "제일 서운" 질문 **9번.** 질문 지침의 예시 그대로다.
- "일부러 … 아니" 해명 **10번.** Core 예시와 "마지막 대화 전까지 유지" 규칙이 같이 민다.

정해진 화해 흐름 (마지막 마디 전에는 합의하지 않는다는 같은 내용이 여러 곳에 있음):
1. Core "마지막 대화 전까지 유지한다" (두 Core)
2. `BAND_GUIDE` 세 구간 모두 "마지막 마디 전에는 … 합의하지 않는다"
3. `SCORING_RUBRIC` "마지막 마디 전에는 10 이상을 줬더라도 … 결론 내리지 않는다"
4. `chooseMove` (`rules.ts`): 중간 마디는 서버가 반론 70% / 질문 30%로 정한다. 수긍·여운은 중간에 나올 수 없다
5. **점수는 한 방향으로만 움직인다**: 마디마다 흔든 정도가 0 이상이라 관계가 "나빠지는" 길이 없다. 결렬은 "덜 움직인 것"일 뿐이다. I7의 "악화될 수도 있어야 한다"와 어긋난다.

### Q5. V1~V4는 명백한 모순만 막는가 → **V2·V3는 그렇다. V1 일부와 V4는 반응의 모양을 정한다**

- **V3 장면**: 모순만 판정 호출로 막고 회상·정정은 통과시킨다. 리플레이에서 오탐 0. I6에 맞다.
- **V2 재주장**: 정리된 주장을 "다시 내세울 때"만 막고 감사·회상은 허용한다. I6에 맞다. 다만 장부 기록이 부정확하면 작동하지 않는다 (다음 작업).
- **V1 반복**: 직전 대사와 글자가 60% 이상 겹치면 막는 것은 명백한 반복만 잡는다. 그러나 **"응", "알겠어" 같은 짧은 수용 뒤에는 직전 대사와 3글자 이상 단어 하나만 겹쳐도 막는다** (`replyRepetitionViolation`의 `sharedContentTerm`). 자연스러운 되짚기("그래, 그 약속은 지킬게")까지 막을 수 있다.
- **V4 끝맺음**: 서버가 정한 반론/질문에 맞춰 "반론이면 질문으로 끝내지 마라", "질문이면 질문으로 끝내라"를 강제한다. 형식 검사가 아니라 **반응의 종류를 정하는 검사**다. 여운의 대사·행동 순서 제약은 2026-11-22에 뺐다.

### Q6. 지금 가진 것으로 충분한가 → **재료는 대부분 있다. 순서와 덜어 내기가 문제다**

- Core에 가치·욕구·두려움이 이미 충분히 쓰여 있다. 장부는 누가 무엇을 말하고 정리했는지 준다. 대화 원문 전체가 들어간다. 마음 수치도 있다.
- 부족한 것은 **해석과 욕구를 먼저 쓰게 하는 순서**(Q3)와, 그 판단을 미리 정해 버리는 **예시·결말 고정·끝맺음 지정을 덜어 내는 것**(Q1·Q4·Q5)이다.
- 새 시스템이 꼭 필요하다는 근거는 아직 없다. 캐릭터별 수치 반응(Q2)과 관계 악화(Q4-5)는 기존 구조 안에서 규칙을 바꾸는 문제다.

## 3. 유지할 것

- Core의 가치·욕구·두려움·화가 나는 조건, "미안함과 억울함은 동시에"
- 공통 원칙의 "독립적 판단과 행동", "설득될 수 있음"(예시 문장만 빼고)
- 장부 (사실만 담고 지시가 없다), 엔진 규칙의 정보 경계·역할 확인·시간 지시어(예시 문장만 빼고)
- 대사 프롬프트에 수치만 주고 해석을 맡기는 지금 방식
- V2·V3의 "명백한 모순만" 원칙, 첫 시도만 거부하고 대화를 끊지 않는 정책

## 4. 바꿀 후보 (구분: 프롬프트만 · 순서/상태 갱신 · 새 시스템)

### A. 프롬프트만 바꾸면 되는 것
| # | 바꿀 것 | 기대 |
| --- | --- | --- |
| A1 | 생성 프롬프트의 예시 대사·행동 6곳 삭제 (§2 Q4 표). 필요한 뜻은 원칙으로 남긴다 (예: "다정함은 말보다 행동으로" — 어떤 행동인지는 쓰지 않음) | 라떼·빨대 반복, "제일 서운" 반복 감소 |
| A2 | Core의 "행동의 기본 순서"를 성향 서술로 (예: "감정이 판단보다 먼저 나오는 편이다") | 반응 진행이 매번 같은 모양이 되지 않음 |
| A3 | Core의 "마지막 대화 전까지 유지한다" 삭제. 이미 있는 "쉽게 뒤집지 않는다, 핵심 걱정에 답을 들어야 바뀐다"로 충분 | 플레이어 말에 따라 변화 시점이 달라질 수 있음 |
| A4 | `BAND_GUIDE`(점수 구간 → 행동 묘사)를 대사 프롬프트에서 뺀다 | 점수가 아니라 마음 수치·장부·원문에서 반응이 나옴 |
| A5 | "직전 응답과 반복 금지" 블록의 특정 사례("답장을 바로 하기 어렵다는 설명, 미리 한마디 하겠다는 약속처럼") 삭제 | 사례 패치 제거 |

### B. 순서나 상태 갱신을 바꿔야 하는 것
| # | 바꿀 것 | 기대 |
| --- | --- | --- |
| B1 | **대사 출력 순서: 속마음 → 대사.** `heard`(이 말이 나에게 어떻게 들렸나) · `want`(지금 원하는 것, 부딪치면 둘 다) → `beats`. 저장은 로그용만, 다음 마디 상태로 쓰지 않는다(숨은 지시가 되지 않게) | I4의 "해석 → 욕구 → 반응" 순서. 호출 수 그대로 |
| B2 | **끝맺음을 서버가 고르지 않는다.** 모델이 고르고, 엔진은 상한만 둔다(질문 한 판 2번, 마지막 마디는 질문 금지). V4는 고른 끝맺음의 형식만 본다 | 중간에도 수긍·여운이 가능. 반응의 종류를 캐릭터가 정함 |
| B3 | 수치 갱신 규칙을 캐릭터별로: 같은 발화 행위라도 윤재·서아의 민감도를 다르게 (Core 옆에 작성). 시작 수치도 Core에 맞게 | I4의 "같은 말을 다르게 받아들임"이 상태에도 남음 |
| B4 | 관계가 나빠지는 길: 비난·단정 같은 행위가 흔든 정도를 **줄일 수도** 있게 | I7의 개선·유지·악화 |
| B5 | V1의 "짧은 수용 뒤 단어 하나 겹침" 규칙 완화 (글자 겹침 검사만 유지) | 자연스러운 되짚기 허용 |

### C. 새 시스템이 꼭 필요한 것
- **지금은 없다.** 다만 바꾼 뒤 "그 캐릭터라서 납득되는가"(I7)를 확인하려면 측정이 필요하다. 이것은 실행 중 시스템이 아니라 **평가 도구**다:
  - 같은 플레이어 말을 윤재와 서아에게 주고 반응이 Core에 맞게 다른지 (차이 검사)
  - 같은 말을 여러 번 생성해 표현이 얼마나 다양한지 (반복 표현 비율 — 위의 라떼·"제일 서운" 집계를 정례화)
  - 사람이 블라인드로 "이 반응이 이 인물이라서 납득되나"를 평가

## 5. 해 볼 수 있는 실험 순서 (작은 것부터, 하나씩)

1. **A1 + A5 (예시·사례 삭제)** → 리플레이 두 판 + 위 반복 표현 집계를 전후 비교. 가장 작고, 가장 큰 효과가 예상된다.
2. **B1 (속마음을 먼저)** → 같은 비교 + 속마음과 대사가 어긋나지 않는지.
3. **A2·A3·A4 + B2 (화해 흐름 고정 풀기)** → 마디별 끝맺음 분포, 중간 수긍이 나오는지, 장면별로 납득되는지.
4. **B3·B4 (캐릭터별 상태 갱신, 악화 가능)** → 같은 말에 대한 윤재·서아 차이, 결과 분포에 악화가 생기는지.

각 단계는 회귀 테스트와 리플레이 기준선을 먼저 남기고 바꾼다 ([dialogue-architecture.md](dialogue-architecture.md) §10·§13).

## 6. 가치 실험: Core에 가치 하나를 더하면 해석이 달라지나 (2026-11-24)

- **브랜치:** `value-experiment` (`ledger-frame`에서 분기). 말투 수정(`yunjae-tone`)은 넣지 않았다
- **실행:** `npm run eval -- value --yes` (윤재, 첫 마디, 대사 모델 Terra, 2회)
- **계기:** 서비스 목적은 상대를 달래는 것이 아니라 "서로 서운한 게 있을 때, 상대 기분을 풀어 주면서 내 서운함도 드러내는 것"이다. 평가 이론으로 보면, 같은 말(예: 사과)도 캐릭터가 무엇을 중요하게 여기느냐에 따라 다르게 평가된다. 지금 Core에는 상대가 무엇을 느꼈는지 알고 싶어 하는 가치가 없다

### 6.1 Core 분류 (요약)
- **가치로 이미 있음:** 신뢰(의도를 믿어 주기) · 솔직함(돌려 말하지 않기) · 책임감(지킬 수 있는 약속만) · 얼굴 보고 하는 대화와 행동으로 챙기기 · 연락이 애정 시험이 되지 않기(서아는 가치, 윤재는 두려움) · 아까 한 말을 기억하기(윤재)
- **가치에서 나왔지만 규칙으로 적힘:** "마지막 대화 전까지 유지" · 행동의 기본 순서 · (게임 규칙) 해결책을 먼저 제안하지 않기
- **Core 밖에 박힌 가치:** 점수 구간 묘사(BAND)의 "핵심 입장(하루 종일 연락할 필요는 없다)", 1차 점수 기준의 "반론에 답하면 10 이상"
- **빠진 가치:** 상대가 무엇을 느꼈는지 알고 싶어 하는 것, 누가 더 잘못했는지보다 서로 무엇 때문에 상처받았는지 이해하는 것

### 6.2 설계
- **비교:** 기존 Core vs 기존 Core + 아래 단락 하나 (Core의 "중요하게 생각하는 것" 절 끝). 문장은 사용자가 정했다. 상황별 반응이 아니라 가치관 자체를 적는다

> 윤재는 서로의 상황과 감정을 존중하는 관계를 중요하게 여긴다. 자신의 사정이 이해받기를 바라는 만큼 상대가 무엇을 느꼈는지도 알고 싶어 한다. 갈등에서 누가 더 잘못했는지를 가리는 것보다 서로 무엇 때문에 상처받았는지 이해하는 것을 중요하게 생각한다. 사과도, 서운함의 표현도 상대의 진심을 이해할 수 있는 중요한 단서로 여긴다.

- **플레이어 첫마디 4개:** 사과만 · 사과와 내 서운함 · 내 서운함만 · 비난
- **같게 둔 것:** 장면, 첫 마디, 시작 마음, 1차 결과와 점수(발화마다 1회, 두 조건 공통), 끝맺음 규칙(첫 마디는 모델이 반론·질문 중 고름), 검증기, 대사 모델(Terra)
- **보지 않는 것:** 가치를 넣었더니 사과만 하는 플레이어를 더 거부하는지, 사과와 서운함을 함께 말하는 플레이어를 더 좋아하는지
- **보는 것 (사용자가 블라인드로 판단):** 캐릭터가 상황을 더 자연스럽고 일관되게 해석하는지, 예상 밖의 말에도 자기 가치관에 맞게 반응하는지
- **기록만 하는 것:** 대사에 영향을 준 제약(첫 마디 끝맺음 규칙, MOVE_GUIDE, BAND, 시작 마음, 1차 라벨, 검증기 거부). 점수와 `chooseMove`는 바꾸지 않는다
- **이번 범위:** 가치 하나 추가의 효과만 본다. Core 전체를 가치 중심으로 다시 쓸지는 결과를 보고 정한다
- **한계:** 첫 마디 하나만 본다 (5마디 흐름은 보지 않는다). 발화당 조건마다 2회라 표본이 작다

### 6.3 반영 (2026-11-24)
- 가치 실험 결과(내용은 납득, 말투가 GPT 같음)를 본 뒤 말투 원인을 프롬프트 통합(consolidate@1)으로 먼저 고쳤다
- 그다음 사용자 결정으로 **위 가치 단락을 그대로 윤재 Core에 넣었다** (같은 문장, "중요하게 생각하는 것" 절 끝). 프롬프트 버전 consolidate@2. 서아 Core에는 넣지 않았다
- 통합 프롬프트 + luna 조합에서 가치 단락의 효과는 따로 시험하지 않았다

## 7. 윤재 Core 재구성: 성격은 그대로, 행동을 미리 정하는 지시만 뺀다 (2026-11-24)

- **브랜치:** `core-values` (로컬 `main`에서 분기) · 프롬프트 버전 consolidate@3
- **원칙: 책임 분리.** Core는 인물(성격·가치·믿음·바람·민감점·지금 상태·말투)만 맡는다. 게임 진행(언제 합의할 수 있는지, 해결책을 누가 먼저 꺼내는지)은 엔진(`chooseMove`·BAND·`MOVE_GUIDE`·첫/마지막 마디 지시)이, 반복 방지는 공통 규칙이 맡는다. 같은 행동 규칙을 Core에 겹쳐 두지 않는다
- **지키는 것:** 기존 윤재의 성격·가치관 문장은 지우지 않았다. 새 가치는 더하지 않았다 (6.3에서 넣은 존중 단락은 그대로)
- **입장 유지와 반복의 구분:** "마지막 대화 전까지 유지한다"(언제까지)를 "의도를 믿어주는 것이 중요해서 납득할 이유 없이 접지 않는다"(왜)로 바꾸고, "입장을 지키는 것과 그 입장을 말로 다시 꺼내는 것은 다르다"를 적었다

### 7.1 Core에서 뺀 것과 그 일을 지금 맡는 곳
| 뺀 문장 | 성격 | 지금 맡는 곳 |
| --- | --- | --- |
| 행동의 기본 순서 (들음 → 감정 → 짧게 반응 → 이유 → 인정) | 반응 순서 절차 | 없음 (맡길 필요 없음). 같은 절의 성격 문단은 "핵심"으로 옮김 |
| 흔들려도 해결책에 합의한다는 뜻은 아니다 | 게임 진행 (합의 시점) | `chooseMove`(중간 마디는 반론·질문만) · 첫 마디 지시 · BAND |
| 입장은 마지막 대화 전까지 유지 | 가치에서 나온 규칙 | Core "입장을 지키는 것" (왜 지키는지로 바꿈) |
| 이미 납득한 사실 부정·같은 변명 반복 금지 | 품질 규칙 | 공통 원칙 "설득될 수 있음" 3 · 반복 금지(`REPEAT_RULES`) |
| 기다리게 한 결과에는 먼저 짧게 사과한다 | 가치에서 나온 규칙 | Core 책임감 가치 ("그 결과는 자기 몫이라고 여긴다"). 사과 여부·시점은 윤재가 정함 |
| 해결책은 먼저 제안하지 않는다 | 게임 진행 | `MOVE_GUIDE.counter` · 첫 마디 지시 · BAND seeking |
| 할 수 있는 만큼만 답한다, 한 번의 연락이면 가능한지와 이유만 | 가치에서 나온 규칙 | Core 책임감 가치 |
| 요구를 "계속 연락"으로 키워 방어하지 않는다 | 품질 규칙 | 공통 원칙 "설득될 수 있음" 2 |
| 억울하면 "일부러 그런 건 아니잖아"처럼 말할 수 있다 | 예시 | 예시만 뺌 ("억울하면 바로 드러낼 수 있다"는 성격으로 유지) |
| 납득하면 무엇이 잘못이었는지 짚고 짧게 사과한다 | 반응 지정 | 없음 ("납득한다"까지만 유지) |
| 이미 들은 이야기를 다시 캐묻지 않는다, 질문으로 해결책을 떠넘기지 않는다 | 품질·게임 규칙 | 엔진 "이미 공유한 요구의 처리" · `MOVE_GUIDE.ask` |
| 회의·샌드위치·폰 이야기는 다시 물을 때만 꺼낸다 | 반복 방지 | 공통 반복 금지 규칙. 필요한 사실은 "지금 상태"와 장면 사실이 그대로 가지고 있다 |
| 이미 받아들인 부분을 다시 방어하지 않는다 | 품질 규칙 | 공통 원칙 "설득될 수 있음" 3 |
| 플레이 시 최우선 체크 1~6 | 절차·품질 규칙 | 없음 / 공통 규칙 |

### 7.2 Core를 고쳐도 남는 반응 강제 (이번에는 건드리지 않음)
| 위치 | 강제하는 것 |
| --- | --- |
| `chooseMove` (`rules.ts`) | 2~4마디의 끝맺음을 서버가 정한다: 반론 70% · 질문 30%(한 판 최대 2번, 연속 금지). 중간 마디에는 수긍·여운이 없다 |
| 첫 마디 지시 (`buildNpcPrompt`) | 반론·질문 중 하나만. 수긍·여운으로 끝낼 수 없다. 해결책은 플레이어가 꺼내게 둔다 |
| 마지막 마디 지시 | 수긍·반론·여운 중 고르게 하고, 질문은 고를 수 없다 |
| `MOVE_GUIDE` | 반론: 받아칠 것, 해결책·약속·규칙을 먼저 제안하지 않을 것, 질문으로 끝내지 않을 것. 질문: 상대 마음을 하나 묻기(예시 "무엇이 제일 서운했는지"). 수긍: 머쓱하게 짧게 + 조건 하나. 여운: 대사 1문장 이하 |
| BAND (`content.ts`) | 점수 구간별 마음 묘사. firm은 "핵심 입장(하루 종일 연락할 필요는 없다)은 바꾸지 않는다", 흔들림·많이 흔들림·받아들임은 "마지막 마디 전에는 합의하지 않는다", 많이 흔들림은 "먼저 해결책을 내지 않는다" |
| 점수 기준 (1차, `SCORING_RUBRIC`) | 캐릭터의 가치를 Core 없이 다른 모델이 채점한다. 새로 넣은 존중 가치는 점수에 반영되지 않는다 |

### 7.3 알고 있는 빈틈 (기록만)
- 공통 반복 금지(`REPEAT_RULES`)는 **직전 대사**의 재진술만 다룬다. Core에서 뺀 "하루(회의·샌드위치·폰) 재연 금지"는 두 마디 이상 떨어진 반복까지 막던 문장이었다. 실제 대화에서 그 반복이 다시 보이면 공통 규칙 쪽에서 다룬다
